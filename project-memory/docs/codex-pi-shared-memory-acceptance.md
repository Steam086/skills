# Codex 和 Pi 共用项目记忆的验收标准

## 目标

Codex CLI 与 Pi 在同一项目中必须读写同一份项目记忆。宿主适配器可以不同，但记忆目录、主题内容、来源信息、访问策略和检索索引只能有一个权威副本。

## 统一数据目录

- 项目记忆根目录固定为 `<project>/.project-memory/`，并可由显式配置覆盖。
- QMD 配置与索引位于 `<project>/.project-memory/.qmd/`，以满足 QMD 2.8.3 的本地配置发现和信任路径约束；QMD collection 只扫描 `.project-memory/`。
- 两个宿主对同一项目解析出相同的 `projectRoot` 和 `memoryRoot`，从而访问相同的主题、旧格式笔记、恢复数据、配置和 QMD 索引。
- Pi 的旧 `.pi/memory`、`.pi/memory-config.json` 和 `.qmd` 数据不得继续成为另一套可写记忆源。
- 项目记忆默认受 Git 忽略保护；安装和迁移不自动授予 Pi、Codex 或 QMD 信任。

## 宿主接入与行为一致性

- 共享核心不依赖 Pi SDK、Codex SDK、MCP 传输或宿主 UI；Pi Extension 与 Codex MCP Server 仅负责适配工具调用。
- 两个适配器暴露相同的工具名称、参数约束、权限错误、分页规则和返回字段。
- 在任一宿主写入或修订主题后，另一宿主能读取相同 ID、内容、修订号、来源锚点及新鲜度状态。
- 共享 Skill 是行为策略的单一来源；工具实现而非 Skill 文本执行访问控制和数据校验。
- Codex 原生本机记忆保持独立，不与项目记忆自动复制或同步。

## 权限、来源与并发安全

- `manual`、`code-research`、`off` 以及独立读写门控在两边含义一致；宿主工具不得自行提升权限。
- `analysis` 写入必须满足启用研究模式、已核实内容和非空源码锚点等现有约束；修订已有主题必须使用预期修订号。
- 源码锚点与哈希在两边使用同一格式；源码变化会标记为 stale 并要求重新核验，不得被当作已验证结论。
- Pi 与 Codex 同时更新同一主题时不得静默覆盖；并发冲突必须返回明确错误或要求重新读取。
- 路径解析拒绝符号链接逃逸、包目录误用以及落到其他项目或用户级记忆目录。

## 迁移与兼容

- 迁移先提供 dry-run，报告来源、目标、冲突和校验哈希；默认不修改源目录。
- 应用迁移不得静默覆盖目标、删除旧数据或双写；目标冲突必须停止并保留两边数据供人工处理。
- 迁移后主题 ID、正文、修订、锚点、旧格式笔记和恢复记录保持一致，且支持回滚到迁移前目录。
- 缺少 QMD 配置、模型或服务时，普通读取不得自动下载模型、启动服务、授予信任或重建索引。

## 交付检查

- Pi 原有工具和项目读取路径保持兼容，Codex MCP Server 可独立运行且不加载 Pi SDK。
- 契约检查覆盖两宿主共享相同数据根、工具 schema 和错误语义。
- 双向读写、stale 标记、读写门控、修订冲突、并发更新、迁移冲突和回滚都有明确验证步骤。
- 安装说明解释共享目录位置、Codex MCP 配置、Pi Extension 加载、信任边界和迁移方法。
