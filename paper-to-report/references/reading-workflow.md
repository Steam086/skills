# 论文阅读与审校

本规范保存可复用的论文阅读、证据审校与内容交接方法，不包含或默认继承任何特定论文的结论。

先看摘要、引言、结论与系统总图，写出研究问题、代价、核心机会和作者主要 claim。再通读机制及实验，回头修正主线。记录实际阅读范围，不把“摘要已读”标成“全文已审”。附录、不可获取附件和扫描页分别标注。

`review.md` 采用紧凑结构：

1. 来源登记：标题、作者、版本/发布日期（未知则直说）、采集日期、URL、本地文件、SHA-256、PDF 页数、页码口径、适用范围。
2. 主张审校表：claim、证据类型、PDF 页/section/figure、原始值与条件、审校判断、对应 slide ID。
3. 冲突清单：正文值、图注值、图中值、独立计算、采用口径及原因。未解决冲突可收窄/撤下相关结论，不必阻止整场报告。
4. 概念表：术语、一句话定义、首次使用页、定义页、隐藏页后是否仍可理解。不预设听众熟悉系统名或缩写。
5. 路线与时间：按 slide ID 给主讲/可选页和秒数，注明预算而非排练实测；短版保留方法所需定义、实验设置与最关键失效条件。

## 证据分层

- `paper`：作者报告的机制或结果，不自动升级成通用定律。
- `teaching`：讲者简化示意/算例，列前提，不伪装成论文原图或实验。
- `inference`：归纳、算术核对或个人推导，列推导条件。
- `research`：本人研究定义或代码支持的能力，记录来源/commit；未提交文件另记哈希。
- `proposal`：拟议方案、假设、未执行实验，页面和讲稿标明未验证。

## 读实验图

先讲图回答什么，再讲横轴、纵轴、单位、曲线/颜色、baseline 和控制条件，最后讲可比较点与趋势。mean/P99、requests/s/tokens/s、用户数/并发/batch、不同硬件或模型不混用。加速比写清分子分母。消融只支持已测条件下的影响，不把几个百分比相加。

保留原图坐标轴、图例和必要注释。正文和图注冲突时展示原值、注明采用范围，不通过重绘掩盖冲突。低清图先高分辨率重裁，不臆造数据点。自制图标明 schematic / illustrative；生成图像不能取代实验结果。

复合图先记录父图定位、原子图标识、各组回答的问题和共享条件。对象数量、空白分隔和图号都不能单独决定裁片数量；检查图例、标签或脚注是否位于图形对象之外。共享轴、跨组连线或缺失共同图例时，不把不完整的片段当作可独立解释的图。

总览可以并排展示独立图组；需要读数、分析误差或异常时，优先每页聚焦一个问题。只有用户明确要求才固定页数；拆页后同步比较条件、读图方向、证据和时间。交接 `figure.parent/panel/required_elements/shared_context`，不把单篇论文的指标数、实验平台或裁剪框写入通用模板。具体裁剪和最终尺寸判断交由渲染 skill 的配图规范。

## 内容交接

旧大纲可以手动迁移为 `deck.json`。标题加一句主题不算完整可渲染大纲，需补齐英文可见内容、图选择、中文讲稿、来源、布局和时间。每次先改 JSON，再重生 Markdown 视图和 PPT，不分别维护三份正文。

需要本人研究联系时另写 `research-map.md`：论文机制 → 本人问题 → 现有源码/材料支持 → 新假设 → 最小对照实验 → 失效边界。计划、模拟器、stub 与真实数据面能力分别说明。没跑实验不写收益指标。
